# Создание тестов «Айрен» (.itx)

## 0. Состав скилла

```
SKILL.md               — этот файл: формат, методика, процесс
scripts/iren_tools.py  — проверка, сборка, распаковка и сводка тестов (Python 3, stdlib; см. раздел 10)
```

Python-скрипт кроссплатформенный и не требует ничего, кроме стандартной библиотеки. Если в проекте установлен MCP-сервер iren-mcp — можно использовать его инструменты (iren_validate_itx, iren_pack_itx и др.), они делают то же самое.

## 1. Что такое .itx

`.itx` — ZIP-архив, содержащий:

```
test.xml          — вся структура теста (UTF-8)
images/*.png      — картинки, на которые ссылаются вопросы
```

Корень XML: `<irenTest version="6">`. Порядок внутри: `section` → `profiles` → `testInfo`.
Профили и `testInfo` необязательны (тест «Страны.itx» работает без них — применяется стандартный профиль).

## 2. Каркас файла

```xml
<?xml version="1.0" encoding="utf-8"?>

<irenTest version="6">
  <section title="Название раздела">
    <questions>
      <!-- вопросы -->
    </questions>
    <!-- необязательно: вложенные секции -->
    <sections>
      <section title="Подраздел">
        <questions> ... </questions>
        <modifiers> ... </modifiers>
      </section>
    </sections>
  </section>
  <profiles>
    <profile title="Название профиля"> ... </profile>
  </profiles>
  <testInfo lastGeneratedTag="12"/>
</irenTest>
```

Правила:
- `tag` — уникальный в пределах теста номер вопроса. Не обязан идти по порядку и не обязан совпадать с позицией в файле. `lastGeneratedTag` = максимальный использованный тег.
- Секция содержит `<questions>` и/или `<sections>`; верхний уровень может быть чисто контейнером секций. Вложенность — до трёх и более уровней (пример: корневая секция без своих вопросов → группы «Двух- и трёхлинейные» → подразделы «3/2», «2/2»):

```xml
<section title="Пневмораспределители">
  <sections>
    <section title="Двух- и трёхлинейные распределители">
      <sections>
        <section title="Распределители 2/2">
          <questions> ... </questions>
        </section>
        <section title="Распределители 3/2">
          <questions> ... </questions>
        </section>
      </sections>
    </section>
  </sections>
</section>
```

- В текстовых атрибутах XML экранировать: `&lt;` `&gt;` `&quot;` `&amp;`. Символы Unicode (≤, ≥, °, —) пишутся как есть.

## 3. Модель содержимого `<content>`

Внутри `<content>` — последовательность элементов:

```xml
<content>
  <text value="Текст вопроса."/>
  <br/>
  <img src="images/1.png"/>
  <formula source="p = F/S"/>
  <text value="Продолжение текста."/>
</content>
```

`<content>` используется: в вопросе, в каждом `<choice>`, в baseItem/matchingItem, в sequenceItem, в categoryTitle, в categoryItem, в дистракторах.

## 4. Типы вопросов

Общие атрибуты: `<question type="..." tag="N" weight="1" enabled="true">`. `weight` — вес в баллах. `enabled="false"` — черновик/отключённый вопрос (не показывается; не удалять, а отключать).

### 4.1 select — выбор ответа

```xml
<question type="select" tag="1" weight="1" enabled="true">
  <content>
    <text value="Вопрос ..."/>
  </content>
  <choices>
    <choice correct="true" fixed="false" negative="false">
      <content><text value="Верный вариант"/></content>
    </choice>
    <choice correct="false" fixed="false" negative="false">
      <content><text value="Дистрактор"/></content>
    </choice>
    <choice correct="false" fixed="true" negative="true">
      <content><text value="Среди предложенных вариантов нет верного."/></content>
    </choice>
  </choices>
  <modifiers>
    <modifier type="suppressSingleChoiceHint"/>
  </modifiers>
</question>
```

- Несколько `correct="true"` = множественный выбор.
- Паттерн «нет верного»: `correct="false" fixed="true" negative="true"`. `fixed` — не перемещается при перемешивании, `negative` — помечает вариант как «негативный».
- `suppressSingleChoiceHint` — отключает подсказку программы о том, что верный ответ один (мешает угадыванию).
- **«Нет верного» — два механизма, совмещать нельзя:** (1) явный вариант с `fixed="true" negative="true"`; (2) модификатор секции/вопроса `addNegativeChoice`. Оба сразу дадут задвоение «Среди предложенных вариантов нет верного.» — утилита `iren_tools.py` такое ловит (как и два явных негативных варианта).

### 4.2 input — ввод ответа

```xml
<question type="input" tag="2" weight="1" enabled="true">
  <content><text value="Город ... — столица Норвегии."/></content>
  <patterns>
    <pattern type="text" value="Осло" quality="1.0000" caseSensitive="false"
             spaces="normalize" numericAware="true" precision="0" wildcard="true"/>
    <pattern type="text" value="Oslo" quality="1.0000" caseSensitive="false"
             spaces="normalize" numericAware="true" precision="0" wildcard="true"/>
  </patterns>
</question>
```

- Несколько `<pattern>` — синонимы и варианты написания (полная форма/аббревиатура, «Снизу вверх»/«Снизу-вверх»).
- `spaces="normalize"` схлопывает пробелы, но НЕ убирает запятые — для ответов вида «5 линий, 3 позиции» давай паттерны с запятой и без: `5 линий, 3 позиции` / `5 линий 3 позиции` / `пять линий, три позиции`.
- `numericAware="true"` — сравнивать числа по значению; `precision` — допуск для чисел (например, `0.001`); `wildcard` — допуск вариаций.

### 4.3 match — соответствие

```xml
<question type="match" tag="3" weight="1" enabled="true">
  <content><text value="Установите соответствие ..."/></content>
  <matchOptions baseItemsUsed="all" distractorsUsed="all"/>
  <pairs>
    <pair>
      <baseItem><content><text value="Левый элемент"/></content></baseItem>
      <matchingItem><content><text value="Правый элемент"/></content></matchingItem>
    </pair>
  </pairs>
  <distractors>
    <distractor><content><text value="Лишний правый элемент"/></content></distractor>
  </distractors>
</question>
```

Пары задаются в правильном соответствии; при показе правые элементы перемешиваются.

**Ориентиры объёма (норма «15–20 вариантов» относится только к select):** match — 4–6 пар и 2–3 дистрактора; input — 2–4 паттерна, покрывающих варианты написания ответа.

### 4.4 order — упорядочение

```xml
<question type="order" tag="4" weight="1" enabled="true">
  <content>
    <text value="Расположите ... в порядке ..."/>
    <br/>
    <text value="Примечание: пояснение направления сортировки."/>
  </content>
  <orderOptions sequenceItemsUsed="all" distractorsUsed="all"/>
  <sequence>
    <sequenceItem><content><text value="Первый"/></content></sequenceItem>
    <sequenceItem><content><text value="Второй"/></content></sequenceItem>
  </sequence>
  <distractors>
    <distractor><content><text value="Лишний элемент"/></content></distractor>
  </distractors>
</question>
```

`<sequence>` — строго в правильном порядке. Если направление порядка неоднозначно (сверху-вниз? с запада на восток?), добавляй пояснение отдельной строкой.

### 4.5 classify — классификация

```xml
<question type="classify" tag="5" weight="1" enabled="true">
  <content><text value="Распределите по категориям."/></content>
  <classifyOptions itemsUsed="all" minItemsPerCategoryUsed="all"/>
  <categories>
    <category>
      <categoryTitle><content><text value="Категория 1"/></content></categoryTitle>
      <categoryItems>
        <categoryItem><content><text value="Элемент"/></content></categoryItem>
      </categoryItems>
    </category>
    <category>
      <categoryTitle><content><text value="Пустая категория-дистрактор"/></content></categoryTitle>
    </category>
  </categories>
</question>
```

Пустая категория допустима и работает как дистрактор. `itemsUsed` / `minItemsPerCategoryUsed` — `all` или число.

### 4.6 Сценарии (вариативные задания)

Модификатор `script` можно добавить к вопросу любого типа. Код пишется построчно:

```xml
<modifiers>
  <modifier type="script">
    <script line="var"/>
    <script line="  a, b, c: Integer;"/>
    <script line="begin"/>
    <script line="  a := Random(90) + 10; { 10...99 }"/>
    <script line="  b := Random(90) + 10;"/>
    <script line="  c := a + b;"/>
    <script line="end."/>
  </modifier>
</modifiers>
```

- Язык — Паскалеподобный: `var/const/type/begin/end.`, `if/while/repeat/for`, `case`, процедуры и функции (результат — через `Result`), статические и динамические массивы (`array of Integer`, `SetLength`), `mod`, `div`.
- Значения переменных на момент окончания скрипта подставляются вместо маркеров `$(имя)` в текст вопроса, варианты ответов и эталоны (`input`).
- Функции: `Random(n)` → 0..n-1; `RandomFloat` → [0;1); `IntToStr`, `FloatToString(значение, знаков)`, `Pos`, `Copy`, `Chr`, `Ord`, `Length`, `Delete`, `Trunc`, `Sqrt`, `Abs`.
- `Real` при подстановке в текст автоматически округляется до 3 знаков; другая точность — через `FloatToString` в переменную `String`.
- XML-экранирование в коде: `<>` писать как `&lt;&gt;`, `<` как `&lt;`. Строки Паскаля — в одинарных кавычках, тогда `&quot;` не нужен.
- Обязательное требование к вариативности: генерируемые варианты равноценны по содержанию и трудности для всех тестируемых (например, при генерации слагаемых добиваться переноса разряда, а не «10 + 20» кому-то и «79 + 86» другому).
- Дистракторы в сценарных `select`-вопросах генерируются кодом и не должны совпадать с верным ответом и друг с другом (подбирать в цикле `repeat...until`).

## 5. Модификаторы секций и подразделов

Ставятся внутри секции **после всех остальных её детей** (`questions`, а при наличии — и `sections`) и действуют на вопросы этой секции. Подтверждённый по ридеру Айрен порядок детей секции: `questions` → `sections` → `modifiers` (все три опциональны). Любой уровень вложенности — раздел, подраздел, подподраздел — может нести свои модификаторы; в рабочих образцах они всегда стоят в той секции, которая непосредственно содержит вопросы:

```xml
<modifiers>
  <modifier type="addNegativeChoice"/>          <!-- автоматически добавить вариант «нет верного» -->
  <modifier type="suppressSingleChoiceHint"/>
  <modifier type="shuffleChoices"/>
</modifiers>
```

Если `addNegativeChoice` включён на секции — не дублировать явный вариант «нет верного» в каждом вопросе.

## 6. Профили тестирования

Несколько профилей = разные сценарии проведения одного теста (обучение / контроль).

```xml
<profiles>
  <profile title="Обучение">
    <questionSelection questionsPerSection="all" shuffleQuestions="true"/>
    <sessionOptions durationMinutes="unlimited" editableAnswers="true"
                    browsableQuestions="true" weightCues="false"/>
    <testResults percentCorrect="true" points="true" mark="true">
      <questionResults percentCorrect="true" points="true" correctAnswer="false"/>
    </testResults>
    <markScale>
      <marks>
        <mark title="2 (неаттестация)" lowerBound="0.0000"/>
        <mark title="3 (удовлетворительно)" lowerBound="0.6500"/>
        <mark title="4 (хорошо)" lowerBound="0.7500"/>
        <mark title="5 (отлично)" lowerBound="0.9000"/>
      </marks>
    </markScale>
    <modifiers>
      <modifier type="shuffleChoices"/>
    </modifiers>
  </profile>
  <profile title="Оценивание знаний">
    <questionSelection questionsPerSection="all" shuffleQuestions="true"/>
    <sessionOptions durationMinutes="17" editableAnswers="false" browsableQuestions="false" weightCues="false"/>
    <instantFeedback answerCorrectness="false" totalPercentCorrect="false"/>
    <testResults percentCorrect="false" points="false" mark="true"/>
    <!-- та же markScale -->
  </profile>
</profiles>
```

> **ОБЯЗАТЕЛЬНОЕ ПРАВИЛО (Айрен падает при нарушении любой из двух проверок):**
> 1. Если в профиле **нет** `<sectionProfile>` — `<questionSelection>` обязан содержать `questionsPerSection` (обычно `"all"`).
> 2. Если `<sectionProfile>` **есть** — в `<questionSelection>` **не должно быть** `questionsPerSection` (сэмплирование задаётся только через sectionProfile). Совмещение роняет открытие второй проверкой ридера.
> BAD: `<questionSelection shuffleQuestions="true"/>` без sectionProfile — «Ошибка при открытии файла» (проверка 1).
> BAD: `questionsPerSection="all"` вместе с `sectionProfile` — «Ошибка при открытии файла» (проверка 2).
> GOOD: `<questionSelection questionsPerSection="all" shuffleQuestions="true"/>` без sectionProfile — безопасный дефолт для обоих профилей; либо `sectionProfile` **без** `questionsPerSection` (как в рабочих файлах). Валидатор ловит оба нарушения как ошибки.

- `durationMinutes` — число или `unlimited`.
- Профиль «Обучение»: время без лимита, можно править ответы и листать вопросы, подробные результаты.
- Профиль «Оценивание знаний»: таймер, без правок и навигации, без обратной связи, по итогу только оценка.
- Выборка по секциям: вместо `questionsPerSection` использовать `sectionProfile` с процентами. `questions="51%"` означает «взять 51% вопросов этой секции». Внешний `sectionProfile` ссылается на секцию по `title`, вложенный список перечисляет её подразделы:

```xml
<questionSelection shuffleQuestions="true"/>
<sectionProfile title="Имя корневой секции" questions="51%">
  <sectionProfiles>
    <sectionProfile title="Имя подраздела 1"/>
    <sectionProfile title="Имя подраздела 2"/>
  </sectionProfiles>
</sectionProfile>
```

- При вложенности 2+ уровней поведение выборки по подразделам недокументировано — если нужна выборка, либо перечисляйте в `sectionProfiles` только конечные секции, либо не используйте выборку вовсе (`questionsPerSection="all"`). Утилита проверяет, что все `sectionProfile` ссылаются на существующие секции.

## 7. Формулы (TeX)

- Формула — элемент `<formula source="TeX-разметка"/>` внутри `<content>`; в редакторе вставляется правым кликом → «Вставить формулу» (появилось в версии 0.2020.08.1). Разделитель `$...$` внутри `source` не пишется: `<formula source="m"/>`, `<formula source="V"/>`, `<formula source="^3"/>`.
- В редакторе формул есть кнопка со справкой — открывает в браузере небольшой гайд по TeX-разметке.
- Движок формул установлен (из файлов программы 0.2020.08.1): **MathJax 2.x с выводом в SVG**, в комплекте пакеты **AMSmath, AMSsymbols, boldsymbol, mathchoice**. Поддерживается TeX-диалект MathJax 2 + эти пакеты; сторонние пакеты (mhchem, cancel и т. п.) и неизвестные символы/макросы НЕ отрисовываются — формула ломается (в рендерере есть детектор неизвестных символов).
- **Каждую формулу обязательно проверять визуально** в режиме «Просмотр». Сложные конструкции вводить по одной и сразу проверять; если конструкция не отрисовывается — упростить или заменить картинкой.

## 8. Методика качественных тестов (стиль заказчика)

Это ключевой раздел. Тесты делаются сложными и «непроговариваемыми»:

1. **Каждый вопрос привязан к источнику.** Формулировки — близко к тексту учебника/лекции («Как называется…», «Что гласит закон…», «Что изображено под цифрой N?»). Один вопрос — одна идея. Перед написанием вопроса находить точное место в источнике; правильный ответ брать из источника, а не по памяти.
2. **Много вариантов (10–20), и все похожи.** Вместо «4 варианта, 3 явно неверные» — длинный список вариантов, различающихся только одной-двумя деталями (например, полные описания УГО: тип управления, НЗ/НО, моно-/бистабильный, 3/2 vs 5/2 vs 5/3, центр закрытый/открытый). Дистракторы — правдоподобные утверждения из той же предметной области, а не абсурд. Угадать почти невозможно; отвечает только тот, кто знает, либо соображает быстро.
3. **Расчёт на поиск по странице.** Тестируемый может использовать поиск (Ctrl+F), чтобы успеть отвечать, — это легальная часть замысла. Поэтому: варианты пишутся полными самодостаточными формулировками (поиск по ключевому слову находит подходящие варианты, но не выделяет верный), вопрос при этом не содержит слов, которые однозначно «подсвечивают» правильный вариант. Тест объёмный, время в профиле контроля ограничено.
4. **Серии однотипных вопросов** (определения, приборы, законы, «что на рисунке») — с одним и тем же набором вариантов, у которых переставлена отметка правильного, плюс `shuffleChoices`. Одна картинка переиспользуется серией вопросов («Что изображено под цифрой 1/2/3?»).
5. **Паттерн «Среди предложенных вариантов нет верного.»** — там, где он уместен; в секциях с ним — `addNegativeChoice` + `suppressSingleChoiceHint`.
6. **Два профиля:** «Обучение» (без лимита, с разбором) и «Оценивание знаний» (таймер, без обратной связи, оценка по шкале 2/3/4/5: 0 / 0.65 / 0.75 / 0.9). Шкала — по согласованию с заказчиком.
7. **Картинки — полноценный источник вопроса:** УГО элементов, фото узлов, контуры, схемы. Картинка должна быть читаемой, а указанная деталь — однороднозначно видна. Минимальное разрешение для УГО — **400 px по ширине** (картинки 100–150 px в редакторе растягиваются, но проверять их на глаз нельзя — только с апскейлом ×5–10). При повторном использовании списка вариантов обязательно пересматривать картинку в увеличении и заново выводить правильный ответ. Если исходные картинки уже 400 px по ширине — перед упаковкой увеличить их ×2–×4 (Pillow, LANCZOS) и класть в тест **увеличенные копии**; визуальную сверку выполнять по увеличенным файлам (сопоставление «вопрос → картинка → ответ» даёт `info --source <тест> --answers`).

**Размер рисунков** (пиксели; ширину и высоту проверяет валидатор по отдельности):
- **минимум** — в размер шрифта, ориентировочно **24×24**; меньше не рекомендуется (16×16 уже нечитаемо);
- рисунок в **вопросе** — максимум **1200×400** (ширина×высота; ширина 1200 — примерно на всю ширину поля вопроса);
- рисунок в **варианте ответа** — максимум **1200×300**: ответов много, крупными рисунками листать устанешь;
- **большие рисунки крайне не рекомендуются** — превышение → валидатор выдаёт предупреждение ИИ, но файл всё равно собирается;
- маленькие рисунки (скриншот формулы или символа, который не удалось вставить стандартными инструментами) допустимы в размер шрифта;
- флаги настройки порогов: `--img-min` (24), `--img-max-w-question` (1200), `--img-max-h-question` (400), `--img-max-w-answer` (1200), `--img-max-h-answer` (300).
8. **Черновики не удалять:** нерешённые/спорные вопросы помечать `enabled="false"`.
9. **Аккуратность текста:** опечатки в формулировках недопустимы (в вопросах-определениях каждый вариант — это определение, ошибка ломает вопрос).
10. **Не включать неоднозначные УГО.** Если символика рисунка не покрыта источником (комбинированные приводы «механика + пилот», нестандартные индексы линий управления, средняя позиция, которой нет в учебнике), вопрос нельзя сформулировать однозначно — такой рисунок в тест не брать; перечень забракованных картинок фиксировать в логе работы.

## 9. Типовые ошибки (реальные примеры — не повторять)

- Правильный ответ не соответствует картинке (скопировали список вариантов из другого вопроса и забыли переставить отметку). Пример: УГО пневмораспределителя с двумя пружинами и пневмопилотами (двустороннее пневмоуправление с пружинным центрированием), а верным помечен «с двойным электропневматическим управлением» (бистабильный, без пружин). Правило: после копирования списка вариантов заново выводить правильный ответ из источника.
- Дубликаты вариантов в одном вопросе («…с механическим фиксатором…» встречается дважды). Правило: проверять уникальность текстов вариантов.
- Варианты не из темы вопроса (вопрос про деталь на фото, варианты — математические знаки). Правило: после сборки перечитывать каждый вопрос целиком.
- У `select`-вопроса не осталось ни одного `correct="true"` (кроме намеренного «нет верного»).
- OCR-текст сканов PDF извлекать как `pdftotext -enc UTF-8 -raw file.pdf out.txt` — в режиме по умолчанию кириллица ломается. Рисунки скана рассматривать постранично: рендерить страницы командой `pdftoppm -f N -l N -r 150 -png file.pdf out` (Poppler). Номер PDF-страницы обычно совпадает с печатной страницей книги — сверять по колонтитулу отрендеренной страницы. По тексту «рис. N» обращаться к изображению.

## 10. Процесс работы

1. Получить материал (PDF/книга/лекция). Извлечь текст, изучить структуру (главы, разделы), посмотреть рисунки.
2. Согласовать с заказчиком: объём (число вопросов и разбивка по секциям), типы вопросов, профили, шкалу оценок, время.
3. Составить план покрытия: по каждому разделу — какие факты/умения проверяются и каким типом вопроса. Определения — `select`-серии и `input`; последовательности/структуры — `order`; классификации — `classify`; соответствия — `match`; распознавание по картинке — `select` с `img`; расчёты — `input` (или сценарии).
4. Написать `test.xml`, положить картинки в `images/`. Проверить и собрать .itx скриптом скилла:

   ```
   py "<папка скилла>/scripts/iren_tools.py" build --source <папка теста> [--output <файл.itx>]
   # (в bash/cmd подойдёт и python; python3 на Windows не вызывать — см. раздел 12)
   # другие подкоманды: unpack --source <файл.itx> [--dest <папка>]  |  info --source <файл.itx или папка>
   ```

   Скрипт проверяет: XML, дубликаты тегов, `lastGeneratedTag`, существование всех картинок, `select` без верного ответа, дубликаты вариантов, совмещение двух механизмов «нет верного», одинаковые правильные ответы в сериях вопросов с одним списком, ссылки `sectionProfile`, объявления переменных против подстановок `$(var)` в сценариях — и упаковывает ZIP с корректными путями (`test.xml`, `images/...`). Код выхода 1 = есть ошибки. Опции обзора: `--check-near-dups` (почти-дубли вариантов — вероятные опечатки; по умолчанию выключено, т.к. близкие варианты — часть методики), `--check-images-blank` (пустые PNG); размеры рисунков: `--img-min` (24), ширина вопроса/ответа `--img-max-w-question`/`--img-max-w-answer` (1200), высота `--img-max-h-question` (400) / `--img-max-h-answer` (300). Предупреждения разбирать до сдачи (часть может быть намеренной, например отключённые черновики). Для визуальной сверки «вопрос → картинка → правильный ответ» использовать `info --source <тест> --answers`. Формат его JSON: для select — ключи `images` (список src) и `correct` (список текстов верных вариантов); для match — ключ `pairs` (список `{base, match}`); для input и order ключа `correct`/`pairs` нет (эталоны лежат в `patterns`/`sequence` самого XML); у каждого элемента есть `tag`, `type` и `section`.
5. Прогнать чек-лист, отдать файл и краткое описание структуры (секции, число вопросов, профили).

## 11. Чек-лист перед сдачей

- [ ] XML корректен: экранирование `&lt; &gt; &quot; &amp;`, кодировка UTF-8, одна строка `<?xml ...?>`.
- [ ] Все `img src` существуют в архиве (пути вида `images/N.png`).
- [ ] Теги уникальны; `lastGeneratedTag` = максимум.
- [ ] У каждого `select` есть верный вариант (или это намеренный «нет верного» с `fixed="true" negative="true"`).
- [ ] Нет дубликатов вариантов; дистракторы из той же темы; правильные ответы выверены по источнику (особенно после копирования списков вариантов).
- [ ] `input`: паттерны покрывают варианты написания; для чисел — `numericAware`/`precision`.
- [ ] `order`: последовательность в правильном порядке; направление сортировки пояснено.
- [ ] Скрипты: экранирование в `script line`, равноценность генерируемых вариантов, дистракторы не совпадают с ответом.
- [ ] Профили: у «Оценивания» выключены подсказки и навигация; шкала оценок согласована.
- [ ] В каждом профиле есть `questionSelection` с `questionsPerSection` или `sectionProfile` (иначе Айрен не откроет тест; проверяется валидатором).
- [ ] Формулы: каждая проверена визуально в режиме «Просмотр».
- [ ] Тест открыт в редакторе «Айрен» без ошибок; каждый вопрос показан в «Просмотре» (включая сценарные через «Предложить вопрос заново»).

## 12. Среда (обнаружение инструментов)

Работа может идти на любой Windows-машине — не полагаться на пути конкретного компьютера, а обнаруживать инструменты по цепочке:

- Python: `py` → `python` → типовые пути установки `%LOCALAPPDATA%\Programs\Python\Python<версия>\python.exe` или `C:\Program Files\Python<версия>\python.exe`. **Никогда не вызывать `python3`** — на Windows под этим именем часто псевдоним-заглушка Microsoft Store (код выхода 49, выводит «Python»).
- Все операции с .itx — через `scripts/iren_tools.py` (только стандартная библиотека Python 3, кроссплатформенно): подкоманды `build` / `unpack` / `info`. Вызывать `py` → `python` → типовые пути установки (см. выше); **никогда `python3`**.
- `zip`/`xmllint` в Git Bash обычно не нужны — всё делает iren_tools.py. Для OCR-текстов PDF использовать `pdftotext`, если установлен (Poppler): извлекать с `-enc UTF-8 -raw`.
- В конфигах MCP-серверов указывать абсолютные пути к исполняемым файлам — иммунитет к PATH.
- Если кириллица в консоли искажается — вызывать утилиты как `py -X utf8 ...` и/или перенаправлять их вывод в файл и читать файл (консоль Git Bash может портить UTF-8). Логировать команды с кодами выхода.
- Пока файл теста открыт в редакторе «Айрен», его не править извне: программа не перечитывает файл на лету. Цикл работы: правка → сборка → открыть/переоткрыть в «Айрене».
- Не распространять среди тестируемых автономные HTML/EXE-версии тестов: правильные ответы зашиты в файл и извлекаются без специальных знаний. Для раздачи ученикам — только сетевое тестирование через сервер.
